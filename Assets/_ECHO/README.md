# ECHO — Level 01 «Первый отголосок»

Функциональный greybox для существующего проекта Unity **6000.6.3f1**, URP 17.6.0, Input System 1.20.0. Сцена, prefab Эхо, материалы и ссылки созданы и сохранены самим Unity Editor.

**Обновление UI/UX:** интерфейс переведён на uGUI и TextMeshPro, добавлены MainMenu, настройки, пауза и Timeline. Актуальная документация: [UI/README.md](UI/README.md). Новое управление: R — запись, T — повтор цикла, Tab — временная шкала, Esc — пауза. Q оставлена как совместимая дополнительная команда.

**Уровень 02 готов:** сканер, запись лучей, один Эхо, две двери и совместная активация. Запуск, архитектура и отчёт о проверках: [LEVEL_02.md](LEVEL_02.md).

## Запуск

1. Открыть `Assets/_ECHO/Scenes/Levels/Level_01.unity` и нажать **Play**.
2. WASD — движение, мышь — обзор, Space — прыжок.
3. Встать на жёлтую платформу справа и оставаться на ней примерно 12–15 секунд.
4. Нажать **R**. Игрок вернётся на старт, Эхо повторит записанный маршрут.
5. Подойти к двери. Когда Эхо активирует платформу, пройти к зелёной площадке выхода.

**T** перезапускает текущий цикл, сохраняя прежние Эхо и отбрасывая текущую запись. **Shift+R** полностью сбрасывает уровень. **Esc** ставит игру на паузу и освобождает курсор; повторное нажатие продолжает игру. На экране завершения доступен повтор уровня.

При раннем Q Эхо существует только до конца собственной записи. Если нажать Q сразу после прихода на платформу, времени удержания может не хватить: запишите более длинное ожидание. При бездействии или одном вращении камеры новая копия не создаётся.

## Пересборка сцены и настройки

`Tools → ECHO → Build Level 01` создаёт сцену заново по тому же пути, обновляет материалы и prefab, настраивает ссылки и добавляет сцену первой в список сборки, сохраняя остальные сцены. Повторный запуск не добавляет дубликатов. Ручные изменения сгенерированной сцены будут заменены при пересборке; Unity предлагает сохранить изменённые открытые сцены перед запуском генератора.

В Inspector доступны длительность цикла, частота записи, минимальное перемещение для сохранения, лимит Эхо, скорость/гравитация/прыжок/чувствительность, размеры платформы и выхода, время открытия и закрытия двери. Значения по умолчанию: 30 секунд, 50 Гц, 3 Эхо, 4,5 м/с.

## Архитектура

- `GameManager` владеет состояниями Initializing / Playing / Paused / ResettingCycle / LevelCompleted, командами клавиатуры, курсором и паузой.
- `TimeCycleManager` владеет единой временной шкалой. В одном `FixedUpdate` он двигает игрока, обновляет все Эхо, записывает положение игрока, пересчитывает платформу и дверь, проверяет выход и только затем завершает истёкший цикл. У механизмов и копий нет собственных Update или таймеров.
- `EchoRecorder` пересчитывает наблюдаемую траекторию на временную сетку 50 Гц, сохраняет T=0 и точное конечное состояние. Запись не зависит от количества отрисованных кадров. Взгляд обрабатывается в Update, прыжок буферизуется до следующего физического шага.
- `EchoRecording` хранит независимую копию кадров; бинарный поиск и интерполяция мировых координат/углов обеспечивают воспроизведение. `EchoFrame` содержит время, положение, yaw тела и pitch камеры.
- `EchoManager` создаёт экземпляры prefab и удаляет самые старые при превышении лимита. `EchoPlayback` не имеет камеры или коллайдера и прекращает отображение/взаимодействие при T >= длительности своей записи. Следующий цикл запускает все записи с T=0.
- `PressurePlate` проверяет локальные координаты опорной точки игрока и всех активных Эхо. Перекрытие нескольких участников поддерживается без зависимости от trigger-событий; `OnActiveChanged` доступен для подключения новых механизмов. `PuzzleController` связывает платформу с дверью.
- `DoorController` управляет поднимаемой панелью и индикатором. Защита проёма задерживает закрытие только при уже открытой двери и нахождении игрока непосредственно в проёме. Расстояние от плиты намного превышает путь, который можно пробежать за 0,18 секунды закрытия; одиночный игрок не успевает к двери.
- `LevelCompletion` проверяет только живого игрока. Завершение замораживает управление, запись, механизмы и таймер. UIEventBridge передаёт реальные данные в uGUI-prefab; прежний GameplayUI сохранён как совместимый вход Hint без IMGUI-отрисовки.

Сброс атомарный: состояние ResettingCycle → очистка по необходимости → телепортация → сброс механизмов → T=0 → восстановление Эхо → пересчёт присутствия → новая запись → Playing. Телепортация не попадает в запись.

## Проверки, действительно выполненные в Unity Editor

21 октября 2026 г. запущены **15 Edit Mode и 17 Play Mode тестов**, включая новый UI/UX. Машиночитаемые результаты: `Tests/Results/EditMode.xml` и `Tests/Results/PlayMode.xml`. Подробности UI-проверок — в `UI/README.md`.

Edit Mode:

- Интерполяция координат, pitch, угла через 360° и ограничение времени выборки.
- Независимое хранение записей и отклонение неактивной записи.
- Выборка 50 Гц при нерегулярных наблюдениях, точный конечный кадр, очистка новой записи.
- Прекращение взаимодействия Эхо на конце записи и восстановление при новом цикле.
- Определение присутствия на платформе по ногам, отклонение положения над платформой.
- Двойная сборка сцены без дубликатов и проверка основных ссылок.

Play Mode:

- Автоматическое завершение по таймеру, одновременное присутствие двух копий, уход последней копии с платформы.
- Физический проход от старта на платформу, открытие двери и невозможность пройти одному после ухода с платформы; затем запись маршрута с ожиданием, создание одного Эхо, проход к выходу и остановка времени после завершения.
- Ввод W/Space/Q/R/Shift+R/Esc через виртуальную клавиатуру Input System: движение, прыжок, гравитация, сохранение/повтор/полный сброс, пауза и продолжение. Дополнительно проверяются столкновения со стеной и потолком.
- Десять последовательных циклов с сохранением и повтором, предел в три копии, независимость записей, пауза без смещения Эхо, истечение записей, восстановление и полная очистка объектов.

Длительные игровые сценарии ускоряются через Time.timeScale при неизменном шаге симуляции 0,02 с. Сам маршрут теста проходит через CharacterController; обычный ввод проверен отдельным тестом. Ручной визуальный осмотр сцены, запуска Play, HUD и экрана завершения также выполнен. Полное ручное прохождение мышью не выполнялось.

Повторные проверки: `Tools → ECHO → Validate → Edit Mode tests` и `Play Mode tests`, либо стандартное окно Unity Test Runner. Проверки сцены пересоздают её; сохранить ручные изменения до запуска.

## Ограничения

- Это greybox: без финальных моделей, анимации, звука и сохранений.
- Проверено в Editor Windows; отдельный Windows Player build не собирался.
- Движущиеся платформы, изменения геометрии между циклами и события ручного взаимодействия пока не реализованы. Копии воспроизводят мировые координаты и не пересимулируют столкновения.
- Совместная работа с другими системами паузы потребует общего владельца Time.timeScale. В текущей сцене им является GameManager.
- Программных ошибок в перечисленных проверках не обнаружено. Чувствительность мыши и удобство темпа могут потребовать индивидуальной настройки.

Генерируемые Library/Temp/Logs/UserSettings исключены существующим .gitignore. Ресурсы `_ECHO` поставляются с Unity .meta-файлами.
