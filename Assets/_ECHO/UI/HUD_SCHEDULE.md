# ECHO — HUD и расписание Эхо, 24.10.2026

## Реализация
Обновлён существующий EchoUI.prefab. Один Canvas, UIManager, UIEventBridge и прежние IUIDataProvider/IUICommands сохранены.
Верхний таймер показывает ceil(max(0, Duration-Time)): в начале 00:30, в момент 7 секунд — 00:23, в конце — 00:00.
Округление вверх исключает показ 00:29 сразу после старта. Источник времени — TimeCycleManager, собственного игрового таймера нет.

Слева показывается ЗАПИСИ: N/Capacity. При достижении вместимости появляется краткое предупреждение о следующей замене старейшей записи.
Замена, длительность циклов, запись, воспроизведение и управление не изменены.
Внизу — нейтральная строка игрока и фактические дорожки сохранённых Эхо. Запись янтарная, с отдельными началом и концом; общий вертикальный маркер проходит через все строки.
Сегменты Эхо содержат стабильные номера; голубой/дополнительный холодный оттенок, приглушение ожидания/завершения и красный цвет ошибки.
Ширина — 680 UI-единиц, высота строки Эхо — 10, промежуток — 6; отступ снизу — 36. Пустые строки не отображаются.
Подробный Timeline сохраняет отдельную строку каждой записи, состояния, сканер, F-события, скрытие дорожек, прокрутку, паузу и курсор.
Добавлены границы записей, суммарное число записей, действующая модель лимитов и отображение достоверного конфликтного интервала.

## Распределение интервалов
EchoLaneLayout — чистый C#-компонент без GameObject/MonoBehaviour.
1. Отбрасывает некорректные/пустые интервалы, не создавая вымышленных сегментов.
2. Сортирует по Start, затем стабильному Id.
3. SortedSet хранит пары (конец последнего интервала, номер дорожки).
4. Если минимальный конец <= нового Start, переиспользует эту дорожку; иначе создаёт следующую.
Полуоткрытые границы позволяют [0,8) и [8,16) занимать одну строку.
Результат стабилен, число дорожек равно пику пересечений. Сложность O(n log n).
Алгоритм не проверяет разрешение на сохранение и не меняет игровые записи.

CompactEchoTimelineUI отвечает только за геометрию и представление.
Перерасчёт расположения происходит при изменении Id/границ записей; графические объекты переиспользуются.
Состояния и текущий маркер обновляются из того же UISnapshot, что использует подробный Timeline.

## Две модели и будущая интеграция
UISnapshot.LimitModel:
- SavedRecordingsLimit (значение по умолчанию): Echoes.Count/Capacity.
- ConcurrentEchoLimit: ActiveEchoCount/ConcurrentEchoCapacity, независимо от числа сохранённых записей.
Capacity остаётся прежним максимумом сохранённых записей. Игрок не включается в ActiveEchoCount.

Для будущей системы предусмотрен IUIContextSource. Реальный компонент уровня/правил должен реализовать:
- IsResearch;
- LimitModel;
- ConcurrentEchoCapacity из конфигурации уровня;
- ActiveEchoCount из игровой системы;
- CurrentRejection с причиной и при наличии Start/End/RecordingId.

Компонент назначается в существующем UIEventBridge.ContextSource. При изменении режима/конфликта без тиков игрового времени будущий контроллер должен вызвать уже существующий публичный UIEventBridge.Publish() из своего события. В текущих сценах ссылка пустая: сохранена действующая модель.
Интерфейс не определяет модель по имени уровня или количеству записей. Значения для уровней 1–7 не зашиты в UI.
Research передаётся независимым признаком UISnapshot.IsResearch, сохраняющимся при паузе и открытии Timeline: текст ИССЛЕДОВАНИЕ, без числового отсчёта, движущегося маркера и индикации записи.
Сам режим исследования, остановку симуляции и переход к циклу должен реализовать будущий игровой контроллер.

RecordingRejection — опциональная достоверная информация от игровых правил.
Для нового отказа источник передаёт новый объект; при последующих публикациях сохраняет его, затем очищает CurrentRejection.
При наличии границ обе шкалы кратковременно выделяют данный интервал красным. Без границ выводится только причина.
UI не вычисляет конфликт, не отклоняет сохранение и не удаляет записи.
CurrentRejection должен быть временным уведомлением; при сбросе уровня/смене расписания источник обязан его очистить.

## Применение и проверка вручную
В открытом Editor вне Play Mode: Tools → ECHO → Apply Compact UI.
Команда обновляет UI-prefab, сохраняет MainMenu/оба уровня и восстанавливает открытую сцену; геометрия уровней не пересоздаётся.
Изменения также внесены в источники генерации UI, поэтому повторная сборка интерфейса сохраняет новое оформление.
Полная генерация уровней по-прежнему пересоздаёт уровни — для изменений HUD она не нужна.

Для проверки после будущей интеграции:
- Подключить реальный IUIContextSource; проверить режим исследования и переход к циклу.
- Проверить реальные отказы новой системы и точность переданных конфликтных интервалов.
- Проверить ActiveEchoCount на полуоткрытых границах и конфигурацию лимитов уровней.
- Отдельно проверить собранный Windows Player; эта задача проверяется в Editor.

## Оставшиеся ограничения
Новая игровая система конкурентных лимитов и Research пока отсутствует: реализованы UI-представление, адаптер и проверки на изолированных данных.
Реальный отказ новой системы не проверялся, поскольку она ещё не существует. После её внедрения требуются перечисленные выше интеграционные проверки.
Как и ранее, сохранённые записи не содержат воспроизводимых F-событий; подробный Timeline показывает доступные F-отметки текущего цикла и записанные данные сканера.
Windows Player не собирался; проверка отдельной сборки остаётся ручной. Известных нерешённых ошибок нового HUD в Editor нет.
