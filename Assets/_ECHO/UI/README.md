# ECHO UI/UX — запуск и интеграция

## Открыть интерфейс

- Главное меню: `Assets/_ECHO/Scenes/MainMenu.unity` → Play.
- Сразу в игре: `Assets/_ECHO/Scenes/Levels/Level_01.unity` → Play.
- Пересоздать UI-prefab, MainMenu и обновить UI существующего уровня: **Tools → ECHO → Build UI and Main Menu**. Геометрия существующей Level_01 сохраняется. Старый IMGUI-компонент оставлен как совместимый вход Hint, но больше ничего не рисует.
- Полностью пересоздать greybox: **Tools → ECHO → Build Level 01**. Генератор также подключает актуальный UI-prefab.

## Управление

WASD — движение, мышь — обзор, Space — прыжок. **R** управляет записью, **T** повторяет цикл без сохранения текущей записи, **Tab** открывает/закрывает подробную шкалу, **Escape** — пауза/возврат из окна настроек. **F** вызывает действие доступного объекта, если такой объект реализует `IInteractable`.

Существующая механика автоматической записи в начале цикла сохранена: при стандартных настройках R завершает запись, создаёт Эхо и начинает следующий цикл. Если у TimeCycleManager выключен `AutoStartRecording`, цикл начинается в ожидании; R начинает запись, повторное нажатие завершает её. Сохраняется фактическое время начала, а Эхо ждёт этого времени перед воспроизведением. Дополнительные совместимые команды: Q — как R; Shift+R — полный сброс уровня.

Tab останавливает симуляцию через GameManager и освобождает курсор. У каждой дорожки есть переключатель видимости. Яркие сегменты обозначают реальное движение, приглушённые — ожидание на основании записанных кадров. Шкала только показывает записи, не редактирует их. Для большого количества копий используются ScrollRect.

## Что работает

- uGUI Canvas, CanvasScaler с базой 1920×1080, RectTransform, LayoutGroup, ScrollRect и EventSystem с InputSystemUIInputModule.
- Собственный статический SDF-шрифт с кириллицей на основе бесплатного Liberation Sans из TMP Essential Resources. Источник и лицензия поставляются вместе с TMP-ресурсами, платных зависимостей нет.
- Прицел и контекстная подсказка, событийный таймер, список копий с уникальными ID и состояниями, индикатор записи, компактная и расширенная шкалы.
- Главное меню, выбор первого и второго уровней, пауза, результаты и общее окно настроек.
- Громкость AudioListener, чувствительность мыши, масштаб UI 75–125%, включение анимаций, VSync, разрешение и полноэкранный режим сохраняются в PlayerPrefs. В Editor смена разрешения/полноэкранного режима сохраняется для Player и не меняет окно редактора. В Player настройки экрана применяются при сохранении и при запуске.
- Панели плавно появляются на unscaled time; кнопки реагируют на выделение/нажатие; начало воспроизведения и ошибки выделяются коротким цветовым импульсом. Анимации отключаются настройкой.
- Единственный владелец Time.timeScale — GameManager. Пауза и Timeline восстанавливают прежний темп, а не принудительно ставят 1.

## Контракты

`UIManager.DataProvider` — сериализуемая ссылка на MonoBehaviour, реализующий `IUIDataProvider` и `IUICommands`. В рабочей сцене это **UIEventBridge**. Визуальные компоненты HUD и Timeline не обращаются к EchoRecorder/EchoPlayback и не ищут их по имени.

Поставщик передаёт `UISnapshot` и события `Changed`, `Notice`, `Interaction`, `InteractionOccurred` (реальное действие и время цикла). Снимок содержит номер/время/длительность цикла, состояние и границы записи, попытки, фазу игры и список `EchoUIData` с ID, состояниями и интервалами. Команды Resume / RestartCycle / ReplayLevel / MainMenu маршрутизируются к игровой системе. При подключении другой системы достаточно реализовать эти интерфейсы и назначить компонент в UIManager; визуальные компоненты менять не нужно.

UIEventBridge подключён к событиям GameManager, TimeCycleManager, EchoManager и PlayerInteraction. Также публично доступны события CycleRestarted, LevelCompleted и SynchronizationError. Таймер публикуется с частотой до 10 Гц; шкалы плавно интерполируют только отображение полученного прогресса. Удалённые записи очищаются из кэша, подписки снимаются при выключении/уничтожении. Результаты считают копии, которые действительно участвовали в удержании платформы за прохождение, а не просто все сохранённые записи.

`CrosshairUI.SetInteractable(bool)` и `InteractionPromptUI.SetPrompt(bool, string)` — публичные точки управления. UI не делает raycast. Единственный raycast выполняется игровым PlayerInteraction до 10 раз в секунду. В Level_01 плита и дверь автоматические, поэтому подсказка F к ним намеренно не показывается. Для нового ручного механизма реализуйте `IInteractable` на игровом компоненте; не добавляйте отдельное обнаружение целей в UI.

## Файлы

- `Scripts/UI/Core/`: контракты, UIManager, событийный адаптер, палитра и анимации.
- `Scripts/UI/HUD/`: индикаторы, прицел, подсказка, список Эхо, плавные шкалы.
- `Scripts/UI/Timeline/`: дорожки, сегменты, общий маркер времени, скрытие дорожек.
- `Scripts/UI/Menus/`: пять независимых контроллеров меню.
- `Scripts/UI/Settings/UISettingsManager.cs`: параметры и сохранение.
- `UI/Prefabs/`: связанный EchoUI, строка списка, дорожка и сегмент шкалы.
- `UI/Fonts/`, `UI/Sprites/`: собственный SDF-атлас и простой ресурс шкал.
- `Editor/EchoUIBuilder.cs`: настройка prefab и сцен без ручной сборки.
- Изменены GameManager (новые команды и состояния), TimeCycleManager (события и границы записи), EchoManager/EchoPlayback (ID и состояния), добавлен игровой PlayerInteraction. Физика и решение головоломки сохранены.

## Проверки и ограничения

Выполнены **15 Edit Mode и 17 Play Mode тестов**, все прошли. Актуальные XML-отчёты: `Assets/_ECHO/Tests/Results/EditMode.xml` и `PlayMode.xml`. Проверки запускаются через Tools → ECHO → Validate. Play Mode включает прежние сценарии головоломки и отдельные UI-проверки: Tab/пауза/восстановление темпа, дорожки и ID, ручное начало записи в середине цикла, игровой F и подсказка, применение и сохранение настроек, переходы меню, компоновка в 1280×720, 1920×1080, 2560×1440, 1920×1200 и 2520×1080 при 75/100/125%. Снимки HUD, MainMenu, Settings, Timeline, Pause и LevelComplete создаются тестами в этой же папке и просмотрены при визуальной проверке.

**Демонстрационные данные в сценах отсутствуют:** интерфейс использует настоящую систему Эхо. Временный ручной механизм для теста F существует только внутри автоматизированного теста. UIDemoDataProvider не нужен, поскольку запись и воспроизведение уже реализованы.

**Недоступные функции отмечены честно:** «Продолжить» выключена из-за отсутствия сохранений; после первого уровня доступен переход к Level_02. Музыки и звуковых эффектов нет, вместо неработающих отдельных регуляторов показано пояснение. Master volume реализован. Записанные F-события пока не воспроизводятся Эхо: первый уровень использует только автоматическую платформу, дорожки показывают движение/ожидание и янтарные сегменты сканирования. Сохранение прогресса не добавлялось. Документация второго уровня: [../LEVEL_02.md](../LEVEL_02.md).

Проверки выполняются в Unity Editor Windows. Изменение режима монитора в отдельном Windows Player и сборка Player должны проверяться отдельно; Editor не подменяет эти проверки. Вспомогательные TMP Essential Resources установлены из уже имеющегося пакета uGUI в `Assets/TextMesh Pro/`.
